OAuth Setup Guides

Composio APM Integrations take-home · A searchable OAuth setup library plus live, source-backed research for unfamiliar apps.

View the full GitHub README and source code

The problem

Before a developer can let an AI agent's users connect an app, they need to know whether to create their own OAuth client at all, how to configure it, which permissions matter, whether review blocks launch, and which work still requires a person.

First decision: check whether Composio-managed OAuth is documented for the provider. If available, managed authentication can avoid custom provider registration. When documentation does not establish support, the guide says Unknown rather than guessing.

Try the demo

  1. GitHub: straightforward OAuth setup and ordinary consent, no separate review for standard scopes.
  2. Google: sensitive/restricted scopes and potentially significant verification work.
  3. Shopify: development installation vs. public App Store distribution and review.
  4. Back on the homepage, search an unfamiliar app such as Attio, Cal.com or Miro. The site investigates documentation live; generated guides may be Partial or Draft when critical information is missing.
  5. Review the next action, registration documentation, sources, requirements, agent actions, human takeover, and share or copy the guide.

What's included

16 curated guides plus live generation for providers outside the library. Each guide contains difficulty, hands-on effort, approval wait/Unknown, requirements, step-by-step actions, blockers, source links, and a clear separation of the work an automated researcher performed from work a person must complete.

Guides are also available as structured JSON for coding agents. Generated guides can be shared as compressed URL snapshots and copied as agent setup briefs.

How the research works

  1. Search for official provider documentation using Tavily and fetch relevant pages.
  2. Distinguish user-facing provider OAuth from sign-in/SSO, API keys and unrelated permission systems.
  3. Extract client registration, redirect, scopes, approval and blocker evidence. Reject malformed endpoint URLs and misleading metadata.
  4. Produce Full, Partial, or Draft guidance with confidence and unresolved facts visible.
  5. Where a developer portal is established, optionally attempt a read-only public HTTP reachability check. This does not create an app or test OAuth.

Technical judgment: this is a deterministic, source-backed investigation pipeline, not an LLM and not an automated logged-in browser agent. Full means documentary completeness, not a successful real OAuth test.

Run locally

Node.js 20+ and the Vercel CLI are sufficient; there is no application dependency install step. Provide a Tavily key as a server-side environment variable for live research.

git clone https://github.com/SreeC22/takehomeapmcomposio.git
cd takehomeapmcomposio
export TAVILY_API_KEY="your_tavily_key"
npx vercel dev

The Vercel CLI may prompt you to sign in/link a project. A static preview with library guides only is available with npx serve .. Never commit API keys; local environment files are excluded by .gitignore.

Test and evidence

node scripts/trust-regression.js
node scripts/registration-qa-regression.js
node scripts/assignment-readiness-regression.js

Production checks covered the homepage, library JSON, Composio managed-auth lookup, and fresh research on Attio, Cal.com, Pipedrive, PostHog, Miro and Baserow. These unfamiliar-app guides correctly remained Partial or Draft. The site also underwent logic-level share/handoff testing, though not complete cross-device browser QA.

Corrections include removing bogus metadata-derived OAuth scopes, distinguishing SSO from provider OAuth, preventing dynamic client registration from being described as no registration, validating OAuth endpoints, and downgrading unsupported review claims. See verification log and full results.

Limitations

  • No provider account was signed into, no OAuth app created, no live end-user consent/token exchange performed, and no provider approval submitted.
  • Unfamiliar documentation can be incomplete or gated. Scope lists, portal URLs, review conditions and effort estimates may remain Unknown and should be rechecked before launch.
  • Managed-OAuth availability comes from public Composio documentation; it is not a complete authenticated toolkit inventory.
  • Generated guide links are self-contained URL fragments rather than server-stored records; they can be long.
  • This is a focused take-home slice, not the planned full 100-app library.
